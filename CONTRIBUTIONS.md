## Module 1 — AI-Generated Hints

### What It Does

When a team is stuck on a question, they can request a contextual hint generated by Gemini AI. The hint nudges the team toward the correct answer without revealing it outright. A smart local fallback activates automatically if no API key is configured.

### How It Works

The hint button appears on the active competition question. Clicking it hits `POST /api/questions/:id/hint`. The server runs **5 sequential guardrails** before generating or serving a hint:

1. **Team membership check** — user must belong to a team
2. **Attempt gate** — team must have ≥ 2 wrong submissions on that question first (configurable via `HINT_MIN_ATTEMPTS`)
3. **Hint limit** — max 3 hints per team per question (configurable via `HINT_MAX_PER_QUESTION`)
4. **Points check** — team must have enough points to afford the deduction
5. **Point deduction** — 5 pts deducted from team score on success (configurable via `HINT_POINT_COST`)

### Caching

Generated hints are **cached in-memory per question**. The LLM is only called once per question regardless of how many teams request hints — all teams receive the same hint text for the same question.

### API Contract

```
POST /api/questions/:id/hint
Authorization: Bearer <token>

Response (success):
{
  "hint": "Think about what object uses keys but cannot leave your desk...",
  "source": "gemini" | "fallback" | "cache",
  "pointsDeducted": 5,
  "hintsUsed": 1,
  "hintsRemaining": 2,
  "teamScoreAfter": 45
}

Response (not enough attempts):
{ "error": "Hints unlock after 2 incorrect attempts. You have 1 so far.",
  "wrongAttempts": 1, "requiredAttempts": 2 }

Response (limit reached):
{ "error": "Hint limit reached (3 per question). No more hints available.",
  "hintsUsed": 3, "hintsRemaining": 0 }

Response (insufficient points):
{ "error": "Not enough points. A hint costs 5 pts but your team only has 3 pts." }
```

### LLM Prompt Design

```
You are an AI assistant for a competitive programming & riddle quiz platform.
A team is stuck on the following [riddle | MCQ].

Title: {question.title}
Question: {question.description}

Write a 1–2 sentence hint that nudges the team toward the correct answer WITHOUT revealing it.
- Do NOT state the answer or any synonym of the answer.
- Focus on the underlying concept, metaphor, or logical reasoning path.
- Be encouraging and concise.
```

If `GEMINI_API_KEY` is not set, a **topic-aware local fallback** generates a relevant hint based on keywords in the question (FIFO/LIFO, deadlock, hash tables, riddle metaphors, etc.).

## Module 2 — Analytics Dashboard

### What It Does

A rich admin-facing analytics dashboard that aggregates submission data in real time to surface: per-question difficulty analysis, submission volume over time, team performance, and competition highlights — all without adding any new database collections or modifying existing documents.

### Key Metrics

| Metric | Description |
|---|---|
| **Solve rate** | `correct / total attempts` per question |
| **Avg time-to-solve** | Time between a team's first attempt and first correct answer per question |
| **Bottleneck score** | Composite score (60% failure rate + 40% time factor) — higher = harder question |
| **Submission heatmap** | Submission volume bucketed into 5-minute windows across the event timeline |
| **Team standings** | Score, questions solved, completion status per team |

### API Endpoints

All endpoints require `ADMIN` role.

```
GET /api/analytics/overview
→ { totalTeams, totalParticipants, totalQuestions, totalSubmissions,
    correctSubmissions, accuracyRate, teamsCompleted }

GET /api/analytics/questions
→ Per-question: totalAttempts, correctAttempts, solveRate, avgSolveTimeSec, bottleneckScore

GET /api/analytics/teams
→ Per-team: score, rank, questionsSolved, completedAt, memberCount

GET /api/analytics/heatmap?bucketMinutes=5
→ { bucketMinutes, heatmap: [{ timestamp, total, correct, incorrect }] }

GET /api/analytics/dashboard
→ Combined payload (overview + questionStats + topTeams + heatmap) in one round-trip
   — backward-compatible with the existing AdminAnalytics page shape
```

### Frontend Features

The existing (stub) `AdminAnalytics.tsx` page was fully replaced with a rich dashboard:

- **Overview stat cards** — participants, submissions, correct solves, overall accuracy
- **Highlight strip** — top bottleneck question + peak activity window (auto-detected)
- **Per-question solve rate bars** — CSS bars showing accuracy % and attempt volume; questions with bottleneck score ≥ 70 get a `🔥 BOTTLENECK` badge
- **Submission heatmap** — stacked correct/incorrect bars per 5-min time bucket with hover tooltips
- **Top 5 performers** — medal emoji ranking with score, questions solved, and completion status
- **Auto-refresh every 30s** — live during competition; manual refresh button with timestamp

**Zero new frontend dependencies** — everything uses existing Lucide icons and pure CSS.
